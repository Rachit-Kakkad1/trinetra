# Contributing to talent-os

First off, thank you for considering contributing to talent-os. This project is built on the belief that individuals deserve elite-level intelligence infrastructure. By contributing, you are helping build the future of sovereign career management.

## 🏹 Our Philosophy

We maintain an **Elite Engineering Culture**. We prioritize:
- **Precision:** Code should be clean, typed, and intentional.
- **Performance:** 60fps cinematic interactions are non-negotiable.
- **Privacy:** User data is sacred. Local-first is our default.
- **Innovation:** We don't copy patterns; we invent them.

## 🛠️ Getting Started

1. **Fork the Repo:** Create your own copy of the intelligence.
2. **Branching Strategy:** We use a `feature/` and `fix/` naming convention.
   - `feature/neural-memory-graph`
   - `fix/command-palette-latency`
3. **Setup:** Follow the [Setup Guide](docs/SETUP.md).

## 🎨 Design & UX Standards

If you are contributing to the UI:
- Follow the [Design Philosophy](docs/DESIGN_PHILOSOPHY.md).
- Ensure all animations use our standard `cubic-bezier`.
- Respect the **Void** color palette (`#07090F`).
- Use **Space Grotesk** for headings and **Inter** for UI.

## 🧪 Testing & Quality

- All logic must be accompanied by tests.
- We value **High Signal** code—minimal abstractions with maximum impact.
- Linting and Type-checking must pass before any PR is considered.

## 📬 Pull Request Process

1. Update the documentation if your change affects usage.
2. Ensure your PR description explains the **Rationale** (Why), not just the **Change** (What).
3. Tag the relevant agents or systems you've modified.
4. Wait for a review from the core collective.

## 📜 Code of Conduct

By participating, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md).
